# 中国古代钱币知识图谱与数字藏品平台

## 项目简介

本项目是一个面向中国古代钱币研究与展示的数字藏品网站，聚焦于钱币本体信息的结构化表达、数字化展示和用户访问体验。项目以“博物馆式展示”作为设计语言，整合了首页、关于项目、数字藏品、时间轴、本体结构、资源下载等功能模块，目标是将古代钱币的知识信息转化为可浏览、可检索、可扩展的数据资源。

该项目当前实现了前端展示与后端数据接口的结合，支持游客访问和账号登录，并利用 SQLite 数据库存储藏品数据，实现了从静态演示页向“可用原型系统”的过渡。

## 一、项目技术应用

### 1. 前端技术
- HTML5
  - 用于页面结构搭建，形成基础的多模块单页展示。
- CSS3
  - 用于视觉设计，包括馆藏展示页、时间轴、弹窗、卡片布局和博物馆风格色彩体系。
- 原生 JavaScript
  - 实现筛选、搜索、导航切换、弹窗交互、数据渲染和状态控制。

### 2. 后端技术
- Python + Flask
  - 负责提供网站 API、会话管理、登录认证以及数据访问服务。
- SQLite
  - 用于保存藏品信息；适合轻量型项目、原型开发和本地演示。

### 3. 数据管理
- 数据模型采用结构化藏品字段，包括：
  - 名称、时代、类型、材质、产地、年代、形制、书体、钱文、描述、标签、图片地址
  - 符合本体的规范化测度字段：`diameter_cm`、`hole_width_cm`、`rim_thickness_cm`、`weight_g`
  - 图像与文献来源字段：`image_source`、`source_ref`
  - 外部关联字段：`coin_type_id`、`regime_id`、`mint_id`、`era_id`、`material_id`、`shape_id`、`script_id`
- 新增本体实体表：`coin_types`、`regimes`、`mints`、`persons`、`eras`、`regions`、`routes`、`areas`、`materials`、`shapes`、`scripts`、`source_refs`，用于支撑知识图谱的实体层。
- 通过数据库实现藏品数据的持久化，而非仅仅依赖浏览器 localStorage。

### 4. 认证与权限
- 登录弹窗设计，支持两种访问方式：
  - 账号密码登录
  - 游客登录
- 使用 Flask session 保存登录状态。
- 默认账号：
  - 用户名：admin
  - 密码：admin123

### 5. 数据导入能力
- 支持上传单个藏品对象
- 支持批量 Excel 导入
- 支持与图片文件夹配套使用，按 `photo` 列中的名称匹配图片文件
- 将导入的数据写入数据库，便于后续维护和展示

## 四、纯手工启动全流程（不使用 AI）

下面这份说明适合完全手动启动本项目，不依赖任何自动化脚本或 AI 工具。目标是让你从“项目源码”跑到“前端可访问 + 后端可工作 + 数据库已创建 + 功能正常”的完整过程。

### 1. 先确认项目结构

在项目根目录中，确保你看到这些文件：

- `server.py`
- `index.html`
- `app.js`
- `style.css`
- `requirements.txt`
- `data/`

如果这些文件都在，则说明项目已经准备好启动。

### 2. 打开终端，进入项目目录

在 Windows 的 PowerShell 或 cmd 里执行：

```bash
cd D:\Desktop\新建文件夹 (5)
```

如果你使用的是 VS Code 集成终端，直接在项目根目录打开即可。

### 3. 检查 Python 是否可用

先确认 Python 已安装，并且版本符合要求：

```bash
python --version
```

如果输出类似：

```bash
Python 3.10.x
```

说明 Python 环境正常。若提示“不是内部或外部命令”，说明你需要先安装 Python，并把 Python 加入系统环境变量。

### 4. 安装项目依赖

在项目根目录执行：

```bash
pip install -r requirements.txt
```

如果你使用的是虚拟环境，也可以先进入虚拟环境再安装：

```bash
D:\Desktop\新建文件夹 (5)\.venv\Scripts\activate
pip install -r requirements.txt
```

本项目的依赖很少，核心只有 Flask：

```text
Flask>=3.0.0
```

安装成功后，后续就不需要再额外装其他库。

### 5. 启动后端（这是核心）

在项目根目录执行：

```bash
python server.py
```

如果使用虚拟环境：

```bash
D:\Desktop\新建文件夹 (5)\.venv\Scripts\python.exe server.py
```

如果启动成功，终端会输出类似：

```text

* Debug mode: on
* Running on http://127.0.0.1:8000
```

这说明后端已经成功启动，项目的 API 也已经可用。

### 6. 数据库怎么启动？

本项目不用单独启动 MySQL、PostgreSQL 或其他数据库服务，因为它使用的是 SQLite。

SQLite 是一个文件型数据库，不需要额外安装数据库服务。项目启动时，`server.py` 会自动执行：

```python
init_db()
```

这段代码会：

- 检查 `data/` 文件夹是否存在
- 创建 `data/coin_museum.db`
- 创建 `coins` 表
- 如果数据库里没有数据，则自动插入默认的样例藏品数据

所以，数据库的“启动”并不是另起一个服务，而是“后端启动时自动初始化数据库”。

你可以在项目目录中看到：

```text
data/
└── coin_museum.db
```

这表示数据库已经成功创建并初始化。

### 7. 验证数据库和后端是否正常

在浏览器里访问：

```text
http://127.0.0.1:8000/api/health
```

如果返回：

```json
{"status": "ok", "database": "D:\\Desktop\\新建文件夹 (5)\\data\\coin_museum.db"}
```

说明：

- Flask 后端已正常运行
- SQLite 数据库已成功创建
- 项目基础环境正常

### 8. 启动前端（两种方式）

这里有两种前端启动方式，任选其一：

#### 方式 A：直接用 Flask 后端作为前端入口

因为 `server.py` 里配置了静态文件服务，访问：

```text

```

即可直接打开前端页面。

这种方式最简单，因为前端和后端都由同一个 Flask 服务托管。

#### 方式 B：单独启动一个静态资源服务器

如果想让前端和后端分开看，可以在另一个终端中执行：

```bash

python -m http.server 8080
```

然后在浏览器访问：

```text

```

这种方式适合纯前端展示测试。

> 注意：如果后端已经在 8000 端口运行，那么前端静态服务器建议使用 8080，避免端口冲突。

### 10. 全套项目跑通的顺序（最重要）

严格按照这个顺序执行，最稳定：

1. 打开终端
2. 进入项目目录
3. 检查 Python

### 11. 常见问题与解决方法

#### 1）`ModuleNotFoundError: No module named 'flask'`

解决：

```bash
pip install -r requirements.txt
```

#### 2）`python: can't open file 'server.py'`

解决：先切到项目目录：

```bash
cd D:\Desktop\新建文件夹 (5)
```

#### 3）端口已被占用

如果 8000 端口被占用，先关闭占用的程序，或者换端口：

```bash
python server.py
```

若必须修改端口，需要在 `server.py` 里把 `port=8000` 改成其他值，然后重启。

#### 4）页面打不开，出现白屏或报错

先确认：

- 后端是否已经启动
- 访问地址是否正确
- 端口是否冲突
- 数据库文件是否已生成

最好的检查方式：

```text
http://127.0.0.1:8000/api/health
```

如果这个接口能返回正常数据，说明后端和数据库两部分都没问题，前端页面问题通常来自静态文件路径或浏览器缓存。

#### 5）数据库没有生成

说明 `server.py` 还没有正常启动。重新执行：

```bash
python server.py
```

数据库会在启动时自动创建。

### 12. 关闭项目

在运行中的终端里按：

```text
Ctrl + C
```

即可关闭 Flask 服务或静态服务器。

### 13. 最终结论

本项目本质上是一个“前端页面 + Flask 后端 + SQLite 数据库”的轻量全栈项目。它不需要复杂部署，也不需要单独启动数据库服务。

真正的启动逻辑是：

- 先装依赖
- 再启动 Flask 后端
- 后端自动创建数据库
- 再用浏览器访问页面

这样就能把前端、后端和数据库三者串起来，项目完整跑通。

## 五、API 接口说明

### 健康检查
- `GET /api/health`
- 返回服务状态和数据库信息

### 登录与会话
- `GET /api/session`
- 获取当前登录状态

- `POST /api/login`
- 账号登录或游客登录

- `POST /api/logout`
- 注销当前会话

### 藏品数据接口
- `GET /api/coins`
- 获取全部藏品数据

- `POST /api/coins`
- 新增单条藏品

- `POST /api/coins/bulk`
- 批量导入藏品

- `GET /api/stats`
- 获取首页统计数据

### 本体数据接口
- `GET /api/ontology`
- 获取知识图谱本体：实体（coin_types、regimes、mints、persons、eras、regions、routes、areas、materials、shapes、scripts、source_refs）与核心关系类型

### 一键翻译接口
- `POST /api/translate`
- 请求体：`{ "texts": ["首页", "数字藏品"], "target": "en" }`
- 返回体：`{ "data": ["Home", "Digital Collection"], "provider": "volcengine", "failedCount": 0, "fallback": false }`
- 后端会自动去重、分批调用火山引擎机器翻译，并带进程内缓存与重试；未成功项返回空字符串，前端回退到本地词典
- 前端点击导航栏语言按钮即可一键切换中文/英文；翻译中按钮会禁用并显示进度状态

#### 机器翻译凭证配置（必须）

火山引擎 Access Key **不写入源码**，需通过环境变量提供：

```bash
set VOLCENGINE_AK=你的AccessKeyId
set VOLCENGINE_SK=你的SecretAccessKey
```

未设置这两个变量时，`/api/translate` 会返回空结果，前端自动降级为本地词典翻译，其余功能不受影响。
